Пошаговое обучение Git в VS Code

Конспект моего личного обучения Git: от первого локального репозитория до работы с ветками и merge — на примере проекта snake_game.

ОС: Windows 11 · Инструменты: Git + Visual Studio Code

Блок 1

Введение: что такое Git и зачем он нужен

  • Git — система контроля версий: хранит историю изменений файлов и позволяет откатываться назад.
  • Для аналитика это «история версий отчёта», только автоматизированная и удобная.
  • В связке с VS Code можно работать с Git почти без командной строки.
Блок 2

Подготовка окружения

2.1. Установка Git и VS Code

  • Установить Git для Windows с настройками по умолчанию.
  • Установить Visual Studio Code.
  • Проверить, что VS Code видит Git: вкладка Source Control активна, иконка Git отображается.

2.2. Первая тренировочная папка

  • Создать на диске папку проекта, например snake_game или git-training.
  • Открыть папку в VS Code: File → Open Folder....
  • Дальше все действия выполняются внутри этой папки.
Блок 3

Первый локальный репозиторий и коммит

3.1. Инициализация Git в папке

  • Открыть вкладку Source Control в VS Code.
  • Нажать кнопку «Initialize Repository» для текущей папки проекта.
  • Папка становится Git‑репозиторием, и изменения начнёт отслеживать Git.

3.2. Создание тестового файла

  • Создать файл, например snake_game или notes.txt.
  • Написать в нём любой текст.
  • Cохранить Cnrl+S.
  • Убедиться, что файл появился в списке Changes во вкладке Source Control.

3.3. Цепочка: рабочая папка → staged → коммит

  • В Source Control нажать на + рядом с файлом — он попадёт в Staged Changes.
  • Ввести сообщение коммита (например, «Первый коммит») и нажать кнопку Commit.
  • Список изменений станет пустым — значит, состояние проекта зафиксировано.
Блок 4

Работа с изменениями и diff

4.1. Новые изменения в файле

  • Открыть snake_game, изменить одну‑две строки.
  • Cохранить Cnrl+S.
  • Файл снова появляется в списке Changes.

4.2. Просмотр diff

  • Кликнуть по файлу в Source Control, чтобы открыть diff‑редактор.
  • В режиме side‑by‑side слева старая версия, справа новая; в inline‑режиме изменения показываются в одном окне.
  • Закрыть diff‑вкладку, чтобы вернуться к обычному виду файла.

4.3. Второй коммит

  • Добавить файл в Staged Changes через +.
  • Сделать новый коммит с понятным сообщением.
  • Снова убедиться, что список изменений пуст.
Блок 5

Откат изменений: Discard и Undo Last Commit

5.1. Discard Changes (откат незакоммиченных правок)

  • Изменить файл, сохранить его, увидеть файл в списке Changes.
  • Нажать на иконку Discard (стрелка назад) рядом с файлом и подтвердить.
  • Файл вернётся к состоянию последнего коммита, изменения исчезнут.

5.2. Undo Last Commit (отмена коммита, но не правок)

  • Сделать коммит с «неудачными» изменениями.
  • Вызвать команду Undo Last Commit во вкладке Source Control.
  • Коммит исчезнет из истории, но изменения останутся в файлах как незакоммиченные.
  • При необходимости можно дополнительно сделать Discard, чтобы вернуть код к предыдущему стабильному виду.
Блок 6

Ветки: отдельные линии развития проекта

6.1. Идея ветки

  • Ветка — это параллельная версия проекта для экспериментов.
  • Главная ветка обычно называется main.
  • Название текущей ветки видно в статус‑баре VS Code, внизу слева.

6.2. Создание ветки experiment

  • Создать новую ветку experiment от main прямо в VS Code.
  • Переключиться на неё и убедиться, что внизу отображается experiment.

6.3. Работа в ветке

  • Изменить snake_game в ветке experiment и сделать один или несколько коммитов.
  • Переключиться обратно на main — там будет старая версия файла, без экспериментальных изменений.
Блок 7

Объединение веток (merge) в main

7.1. Подготовка

  • Переключиться на ветку main.
  • Проверить, что в main пока нет изменений из experiment.

7.2. Merge ветки experiment в main

  • В VS Code выбрать действие Merge Branch….
  • Указать, что нужно слить ветку experiment в текущую ветку main.
  • После успешного merge открыть snake_game в main и убедиться, что в нём появились изменения из experiment.
Блок 8

Что я уже умею

  • Настраивать Git и VS Code и инициализировать локальный репозиторий.
  • Создавать файлы, отслеживать изменения и делать коммиты через Source Control.
  • Смотреть diff, откатывать незакоммиченные правки и отменять последний коммит.
  • Создавать ветки, работать в них и объединять изменения обратно в main.

Следующий шаг: подключить GitHub, настроить удалённый репозиторий и научиться работать с push/pull из VS Code.
